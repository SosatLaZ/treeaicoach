# Minimap detection: what others do (survey 2026-10) and what fits us

1. **DeepLeague** (farzaa/DeepLeague, 2017): YOLOv2 on ~100k LCS minimaps labelled from the spectator API; good on pro VODs, fails on unseen champions / skins / HUD scales. Lesson: a closed-class detector does not generalise; we keep the roster (10 known portraits) as the class list.
2. **PandaScore** (2018 blog): SSD on DeepLeague100K, then a per-roster model trained on **synthetic minimaps** (icon pastes on map art, rings, blur, occlusion); champions not in the training set fail with plain detection. Same idea as our det_gym / training.real_art renderer.
3. **League-X** (dcheng728/League-X) and YOLO11 minimap models on Roboflow / Hugging Face (cc-by-nc): small YOLO + per-champion classes; licence and class coverage (131/149) rule them out as our engine.
4. **AAAI 2026 student abstract** (Lee, Kim, Kim, GIST "Learning a Champion Detection Model"): transfer learning, synthetic pre-training + a little real replay data, aimed at tiny / occluded icons. Matches our ONNX icon verifier: synthetic first, then the real labelled cases (tests/fixtures/real_cases).
5. **Template matching with circular masks** (common in hobby trackers / Overwolf apps such as LoL Map Tracker): masked NCC of the roster portraits at a calibrated scale. Already our core (roster_matcher: Lab masked NCC in the Fourier domain, live scale calibration).
6. **Identity = (champion, team)**: trackers that key tracks by champion name break in mirror matches (Swiftplay / normals allow the same champion in both teams). The team must be a hard constraint from the ring colour. **Applied here** (see below).
7. **Global one-to-one assignment** (Hungarian on portrait score x motion gate, per team): standard in MOT trackers (SORT / ByteTrack); ours resolves conflicts greedily per champion. Candidate, not tried yet.
8. **Temporal tracking**: Kalman / constant-velocity prediction + re-identification after fog (ByteTrack keeps low-score boxes to bridge occlusions). We have prediction, camera lock, ghosts; low-score bridging inside stacks is the next candidate for the bot-lane misses.
9. **Fog handling**: nobody detects in fog; trackers keep a "last seen" mark and a reachable-area model. Ours: fog_tracker.py (time-bounded last-seen, reachability).
10. **Icon embeddings** (small CNN per crop, cosine to roster embeddings): robust to skins; our identifier already does NCC + HSV histogram features on crops. A learned embedding is a later option (needs a new ONNX model, +~1 MB).
11. **Applied (2026-10-21)**: mirror-safe identity. `identifier._trust_aliases` mapped a matched alias to the LAST roster member with that alias (the enemy copy): my own icon became the enemy in a mirror. Now the member is picked on the detection's side; `Tracker.get_side` + `engine_overlay_state` read the enemy / ally views on their own side (`alias~side` keys). New gym suite `--suite mirror` (mirror_lane: me vs same champion top; mirror_bot: both bot duos mirrored).
12. Result, mirror suite: team errors 193 -> 4, me_bad 0.81 -> 0.11 (mirror_lane 1.00 -> 0.00), recall 0.70 -> 0.82, precision 0.84 -> 0.97. main / botlane suites and the real benches unchanged.
13. Still weak: in a 4-icon mirrored stack the enemy copy is drawn on me for a few frames (4 team errors in mirror_bot); id errors of unrelated champions.
14. Not adopted: YOLO retraining on synthetic minimaps (bigger model, CPU cost, duplicates the roster matcher); external YOLO weights (licence).
15. Sources: github.com/farzaa/DeepLeague, pandascore.co blog (2018-06-22), github.com/dcheng728/League-X, cilab.gist.ac.kr "Learning a Champion Detection Model" (2025-26), kuru1099.itch.io/lolmaptracker.
